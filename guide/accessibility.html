웹 접근성 지침 가이드 (KWCAG 2.2)

한국형 웹 콘텐츠 접근성 지침 2.2(Korea Web Content Accessibility Guidelines 2.2)는 장애인과 고령자를 포함한 모든 사용자가 차별 없이 웹 콘텐츠를 동등하게 이용할 수 있도록 보장하는 4대 원칙과 실무 가이드라인을 제공합니다.

Principle 01

인식의 용이성

모든 정보와 사용자 인터페이스 요소는 사용자가 인지할 수 있는 방식으로 표현되어야 합니다.

Principle 02

운용의 용이성

사용자 인터페이스의 모든 구성 요소는 다양한 보조기술 및 키보드 등으로 제어 가능해야 합니다.

Principle 03

이해의 용이성

정보와 사용자 인터페이스 운용은 논리적이고 직관적이며 이해하기 쉬워야 합니다.

Principle 04

견고성

웹 콘텐츠는 보조기술을 포함한 현재 및 미래의 다양한 사용자 에이전트와 안정적으로 호환되어야 합니다.

🔍

1. 인식의 용이성 (Perceivable)

정보와 사용자 인터페이스 요소는 사용자가 지각할 수 있어야 함
1.1.1

적절한 대체 텍스트 제공

시각 장애 필수 항목

텍스트가 아닌 콘텐츠(이미지, 아이콘, 그래픽 등)에는 그 의미나 용도를 동등하게 파악할 수 있는 대체 텍스트(alt 속성 등)를 명시해야 합니다.

핵심 준수 요건

  • 의미 있는 이미지는 이미지 내용을 온전히 설명하는 alt 속성 작성
  • 장식용 이미지나 배경 요소는 빈 alt=""를 제공하거나 CSS 배경 이미지로 처리
  • 링크/버튼 역할을 하는 이미지(아이콘)는 이동할 목적지 또는 동작을 설명
✕ 미준수 예시
<!-- alt 누락 또는 무의미한 파일명 기재 -->
<img src="graph_2026.png">
<img src="search_icon.png" alt="이미지">
✓ 준수 예시
<!-- 명확한 설명 또는 버튼 목적 기재 -->
<img src="graph_2026.png" alt="2026년 분기별 매출 통계 그래프">
<button><img src="search_icon.png" alt="검색"></button>
1.2.1

자막 제공

청각 장애 필수 항목

멀티미디어 콘텐츠(영상, 음성)를 제공할 경우, 대사·음향 정보를 이해할 수 있도록 동기화된 자막, 대본 또는 수어를 제공해야 합니다.

핵심 준수 요건

  • 동영상 내 <track kind="subtitles"> 태그를 통한 웹 표준 자막(WebVTT) 연동
  • 실시간 오디오/비디오 방송의 경우 실시간 자막 또는 전문 스크립트 제공
✕ 미준수 예시
<video src="intro.mp4" controls></video>
✓ 준수 예시
<video src="intro.mp4" controls>
  <track src="intro_ko.vtt" kind="subtitles" srclang="ko" label="한국어 자막" default>
</video>
1.3.1

색에 무관한 콘텐츠 인식

색각 이상 필수 항목

콘텐츠는 색상만으로 정보를 구별하도록 제공해서는 안 되며, 패턴, 밑줄, 텍스트 레이블, 모양 등을 함께 제공해야 합니다.

핵심 준수 요건

  • 필수 입력 필드를 빨간색 테두리로만 표시하지 않고 '*', '필수항목' 텍스트를 함께 표기
  • 차트나 그래프의 범례에 색상뿐만 아니라 패턴 또는 데이터 레이블 직접 기재
1.3.2

명도 대비 (4.5:1 이상)

저시력자 노안

텍스트와 배경 간의 명도 대비는 최소 4.5:1 이상이어야 합니다. (큰 텍스트는 18pt 이상 또는 14pt 굵은 글꼴 시 3:1 이상 허용)

핵심 준수 요건

  • placeholder나 비활성(disabled) 상태가 아닌 일반 본문 텍스트는 4.5:1 이상의 대비 유지
  • 배경 이미지 위에 텍스트를 배치할 경우 반투명 오버레이를 주어 충분한 대비 확보
1.4.1

콘텐츠 선형화 및 자동 재생 제한

스크린리더 인지 장애

페이지 진입 시 자동으로 소리가 재생되는 콘텐츠는 스크린 리더 음성과 중복되어 사용을 방해하므로, 3초 이상 지속되는 소리의 자동 재생을 금지하거나 제어 수단을 제공해야 합니다.

2. 운용의 용이성 (Operable)

모든 사용자 인터페이스 구성 요소는 키보드 등으로 조작 가능해야 함
2.1.1

키보드 사용 보장

지체 장애 시각 장애 핵심 필수

마우스 없이도 키보드(Tab, Shift+Tab, Enter, Space, 방향키)만으로 모든 대화형 컨트롤(링크, 버튼, 폼 요소 등)에 접근하고 조작할 수 있어야 합니다.

핵심 준수 요건

  • <div onclick="..."> 대신 표준 시맨틱 태그인 <button> 또는 <a> 사용
  • 키보드 초점이 특정 영역에 갇혀 빠져나오지 못하는 '키보드 트랩(Keyboard Trap)' 방지
  • 커스텀 컴포넌트에는 적절한 tabindex="0" 및 키다운 이벤트 바인딩
✕ 미준수 예시
<!-- 키보드로 초점이 가지 않음 -->
<div class="btn" onclick="submitData()">제출하기</div>
✓ 준수 예시
<!-- 시맨틱 태그 사용으로 Tab 및 Enter/Space 기본 지원 -->
<button type="button" onclick="submitData()">제출하기</button>
2.1.2

초점 이동 및 표시 (Focus Indicator)

키보드 사용자 필수 항목

키보드 초점은 시각적으로 명확하게 표시되어야 하며, 초점 이동 순서는 DOM 구조와 논리적 독해 순서에 일치해야 합니다.

핵심 준수 요건

  • CSS에서 outline: none을 적용하고 대체 스타일을 주지 않는 행위 엄격히 금지
  • :focus-visible을 활용하여 키보드 탐색 시 고대비 포커스 링 제공
  • 모달 레이어 팝업이 열릴 경우 모달 내부로 초점을 이동시키고 닫힐 시 기존 트리거 버튼으로 복귀
✕ 미준수 예시
/* 초점 표시 제거로 키보드 사용자 위치 파악 불가 */
button:focus, a:focus {
  outline: none;
}
✓ 준수 예시
/* 명확한 포커스 링 보장 */
:focus-visible {
  outline: 2px solid #6c8fff;
  outline-offset: 3px;
}
2.2.1

정지 기능 제공 (캐러셀/슬라이드)

전체 사용자 인지 장애

자동으로 변경되거나 롤링되는 콘텐츠(메인 슬라이드 배너, 실시간 검색어, 티커 등)는 사용자가 움직임을 멈추거나 다시 시작할 수 있는 정지(일시정지) 제어 버튼을 제공해야 합니다.

2.4.1

반복 영역 건너뛰기 (스킵 내비게이션)

키보드 사용자 스크린리더

상단 GNB 메뉴나 반복되는 헤더 영역을 거치지 않고 웹페이지의 핵심 콘텐츠 영역으로 바로 이동할 수 있는 건너뛰기 링크를 페이지 최상단에 제공해야 합니다.

✓ 건너뛰기 링크 구현 예시
<body>
  <a href="#main-content" class="skip-nav">본문 바로가기</a>
  <header>...</header>
  <main id="main-content">...</main>
</body>
✓ CSS 스타일 예시
.skip-nav {
  position: absolute;
  top: -9999px;
}
.skip-nav:focus {
  top: 10px; left: 10px; z-index: 9999;
}
2.4.2

조작 가능 크기 (최소 24×24px)

모바일/터치 지체 장애

버튼, 링크, 체크박스 등 모든 사용자 상호작용 컨트롤의 유효 클릭/터치 영역은 최소 24×24px 이상의 크기를 확보해야 오작동을 방지할 수 있습니다.

3. 이해의 용이성 (Understandable)

정보와 사용자 인터페이스의 운용은 논리적이고 이해하기 쉬워야 함
3.1.1

기본 언어 표시 (lang 속성)

스크린리더 필수 항목

웹페이지 최상단 <html> 요소에 해당 문서의 주 언어를 명시(lang="ko")하여 음성 낭독기가 올바른 발음 엔진으로 읽을 수 있도록 해야 합니다.

✕ 미준수 예시
<!DOCTYPE html>
<html> <!-- 언어 정보 누락 -->
✓ 준수 예시
<!DOCTYPE html>
<html lang="ko"> <!-- 기본 언어 한국어 지정 -->
3.2.1

사용자 요구에 따른 실행 (새 창 안내)

시각 장애 예측 가능성

새 창(target="_blank")이나 팝업창이 열릴 경우, 사용자가 사전에 인지할 수 있도록 "새 창으로 열림" 텍스트나 아이콘 등의 안내 정보를 제공해야 합니다.

✕ 미준수 예시
<a href="guide.pdf" target="_blank">가이드 문서 다운로드</a>
✓ 준수 예시
<a href="guide.pdf" target="_blank" title="가이드 문서 (새 창으로 열림)">
  가이드 문서 다운로드 <span class="sr-only">(새 창)</span>
</a>
3.3.1

레이블 제공 (폼 컨트롤 연결)

시각 장애 인지 장애 핵심 필수

입력 서식(input, textarea, select)에는 어떤 정보를 입력해야 하는지 명확한 <label>을 연결해야 합니다.

핵심 준수 요건

  • <label for="user-id">와 <input id="user-id">의 id-for 명시적 매핑
  • 디자인상 레이블을 숨겨야 할 경우 스크린리더용 숨김 클래스(sr-only) 또는 aria-label 활용
  • placeholder는 부가 힌트일 뿐 레이블을 대체할 수 없음
✕ 미준수 예시
<!-- label 없이 placeholder만 있는 경우 -->
<input type="email" placeholder="이메일 입력">
✓ 준수 예시
<label for="user-email">이메일 주소</label>
<input type="email" id="user-email" placeholder="example@domain.com">
3.3.2

오류 정정 안내

전체 사용자 인지 장애

입력 서식 작성 시 오류가 발생했을 경우, 오류의 원인과 정정 방법을 텍스트로 명확하게 설명하고 오류가 발생한 입력 필드로 초점을 이동시켜야 합니다.

4. 견고성 (Robust)

웹 콘텐츠는 다양한 사용자 에이전트 및 보조기술과 호환되어야 함
4.1.1

마크업 오류 방지 (문법 유효성)

호환성 보조기술 호환

HTML 문법 오류가 없도록 태그의 시작과 끝이 일치하고 올바르게 중첩되어야 하며, 동일 페이지 내에서 id 속성값이 중복되어서는 안 됩니다.

핵심 준수 요건

  • 태그 중첩 순서 준수 (예: <p><div></div></p> 같은 잘못된 구조 금지)
  • 페이지 내 id 속성 유일성(Unique ID) 보장
  • 속성값의 따옴표 누락 및 오탈자 검수
4.2.1

웹 애플리케이션 접근성 준수 (WAI-ARIA)

동적 UI 스크린리더

동적 UI 컴포넌트(드롭다운 메뉴, 탭, 아코디언, 모달 레이어)에는 상태 정보(펼침/접힘, 선택됨 등)와 역할(role)을 명시할 수 있는 WAI-ARIA 속성을 바르게 적용해야 합니다.

핵심 준수 요건

  • 아코디언/드롭다운 토글 버튼: aria-expanded="true/false", aria-controls="패널ID"
  • 탭 메뉴: role="tablist", role="tab", aria-selected="true/false"
  • 모달 다이얼로그: role="dialog", aria-modal="true", aria-labelledby="제목ID"
✓ 아코디언 토글 버튼 예시
<button type="button" 
        aria-expanded="false" 
        aria-controls="faq-ans-1">
  자주 묻는 질문 1번 제목
</button>
<div id="faq-ans-1" hidden>답변 내용...</div>
✓ 모달 레이어 다이얼로그 예시
<div role="dialog" 
     aria-modal="true" 
     aria-labelledby="modal-title">
  <h2 id="modal-title">공지사항</h2>
  <button>닫기</button>
</div>

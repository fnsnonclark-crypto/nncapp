1. 인식의 용이성 (Perceivable)

4개 지침 · 9개 검사항목
1.1.1

적절한 대체 텍스트 제공

지침 1.1 대체 텍스트 시각장애

텍스트 아닌 콘텐츠(이미지, 버튼 등)는 그 의미나 용도를 동등하게 파악할 수 있도록 적절한 대체 텍스트를 제공해야 합니다.

점검 기준 (Pass)

  • 의미가 있는 이미지는 온전한 설명이 담긴 alt 속성 제공
  • 장식용 배경 이미지는 빈 alt="" 처리 또는 CSS 배경 처리

오류 기준 (Fail)

  • alt 속성 누락 또는 파일명(img01.jpg)만 기재한 경우
  • QR코드, 도표, 캡차 등 중요 정보를 대체 텍스트 없이 이미지만 게시
HTML 코드 가이드
<img src="graph_q3.png" alt="2026년 3분기 사용자 증가율 15% 달성 그래프">
<img src="deco_line.png" alt="" role="presentation">
1.2.1

자막 제공

지침 1.2 멀티미디어 대체 수단 청각장애

영상 및 오디오 콘텐츠는 음성 정보를 이해할 수 있도록 동기화된 자막 또는 원고, 대본을 제공해야 합니다.

점검 기준 (Pass)

  • 동영상 재생과 동기화된 한국어 자막(WebVTT 등) 제공
  • 실시간 음성 콘텐츠에 실시간 자막 또는 대본 전문 제공

오류 기준 (Fail)

  • 대사가 포함된 영상에 자막 및 텍스트 원고가 전혀 없는 경우
1.2.2

음성 해설 제공

지침 1.2 멀티미디어 대체 수단 시각장애

음성 정보만으로는 이해할 수 없는 영상의 중요한 시각적 정보(등장인물 동작, 자막 텍스트, 장면 전환)를 설명하는 화면 해설 음성이나 원고를 제공해야 합니다.

점검 기준 (Pass)

  • 화면 해설 오디오 트랙 제공 또는 장면 설명이 포함된 종합 대본 제공

오류 기준 (Fail)

  • 대사 없는 무성 튜토리얼 영상에서 화면 동작 설명이 부재한 경우
1.3.1

콘텐츠의 선형 구조화

지침 1.3 적응성 스크린리더

콘텐츠는 보조기술 사용자가 문맥을 오해하지 않도록 논리적인 순서(제목 → 본문 → 관련 동작)로 마크업되어야 합니다.

점검 기준 (Pass)

  • CSS 스타일을 제거해도 텍스트의 읽는 순서가 의미적으로 일치함
  • 계층 구조에 맞는 제목 태그(h1~h6) 순차 사용

오류 기준 (Fail)

  • 시각적 배치(flex, grid, float)만 맞추고 DOM 순서는 뒤섞인 경우
1.3.2

표의 구성 (데이터 테이블)

지침 1.3 적응성 정보이해

데이터 표는 행과 열의 제목 셀을 명확히 구분하고 표의 주제를 나타내는 캡션(caption)을 제공해야 합니다.

점검 기준 (Pass)

  • <caption> 제공 및 제목 셀에 <th scope="col/row"> 지정
  • 레이아웃 목적의 테이블에는 role="presentation" 명시

오류 기준 (Fail)

  • 데이터 테이블에 th 없이 모두 td로만 작성된 경우
1.3.3

명확한 지시사항 제공

지침 1.3 적응성 인지장애

지시사항은 모양, 크기, 위치, 방향, 소리 등 단일 감각적 특징에만 의존하여 설명해서는 안 됩니다.

점검 기준 (Pass)

  • "오른쪽 파란 버튼" 대신 "오른쪽 [제출] 버튼"처럼 명칭 명기

오류 기준 (Fail)

  • "아래 둥근 아이콘을 클릭하세요", "빨간색 글씨를 확인하세요"
1.4.1

색에 무관한 콘텐츠 인식

지침 1.4 명료성 색각이상

정보를 전달할 때 색상만을 유일한 구분 수단으로 사용해서는 안 되며, 패턴, 밑줄, 아이콘, 텍스트 레이블을 함께 병기해야 합니다.

점검 기준 (Pass)

  • 필수 입력 필드를 색상뿐 아니라 기호('*') 및 텍스트로 명기
  • 차트 데이터에 색상 외 점선/실선 패턴 및 수치 라벨 직접 표기

오류 기준 (Fail)

  • 현재 페이지 링크를 오직 텍스트 색상 변경으로만 구분하는 경우
1.4.2

텍스트 명도 대비 (4.5:1 이상)

지침 1.4 명료성 저시력

텍스트와 배경 간의 명도 대비는 최소 4.5:1 이상이어야 합니다. (18pt 이상 또는 14pt 이상의 굵은 글꼴은 3:1 이상)

점검 기준 (Pass)

  • 일반 본문 텍스트 명도비 4.5:1 이상 확보 (placeholder 제외)
  • 이미지 배경 위에 배치된 텍스트는 오버레이로 대비 확보

오류 기준 (Fail)

  • 밝은 회색 배경(#f0f0f0)에 연한 회색 글자(#a0a0a0) 배치
1.4.3

배경음 조절 (자동 재생 소리 제어)

지침 1.4 명료성 스크린리더

웹페이지 진입 시 자동으로 3초 이상 지속되는 소리가 재생되지 않도록 하거나, 이를 즉시 정지/음소거할 수 있는 제어 수단을 제공해야 합니다.

점검 기준 (Pass)

  • 기본 상태가 음소거(muted)이거나 재생 제어 버튼이 최상단에 제공됨

오류 기준 (Fail)

  • 정지 컨트롤 없이 배경음악이 무한 반복 자동 재생되는 경우

2. 운용의 용이성 (Operable)

4개 지침 · 14개 검사항목
2.1.1

키보드 사용 보장

지침 2.1 입력장치 접근성 지체장애

모든 기능과 상호작용 컨트롤은 마우스 없이 키보드(Tab, Enter, Space, 방향키)만으로 조작 가능해야 합니다.

점검 기준 (Pass)

  • 링크, 버튼, 폼 양식 등 모든 요소가 Tab 키로 순차 접근 가능
  • 버튼은 Enter/Space, 드롭다운은 방향키로 조작 가능

오류 기준 (Fail)

  • <div onclick="..."> 작성으로 키보드 포커스 불가
  • 마우스 호버(Hover) 시에만 나타나고 키보드로는 열 수 없는 서브메뉴
2.1.2

초점 이동 및 키보드 트랩 방지

지침 2.1 입력장치 접근성 키보드사용자

키보드 초점은 논리적으로 이동해야 하며, 특정 영역(모달 등)에 초점이 영구적으로 갇히는 키보드 트랩이 없어야 합니다.

점검 기준 (Pass)

  • 모달 팝업 오픈 시 내부로 초점 이동, 닫을 때 기존 트리거 버튼으로 복귀
  • ESC 키로 모달 레이어를 닫을 수 있도록 지원

오류 기준 (Fail)

  • 모달이 열렸는데 초점이 배경 페이지에 머물러 헤매는 경우
2.1.3

조작 가능 (단일 포인터 대안)

지침 2.1 입력장치 접근성 지체장애

복합 제스처(두 손가락 핀치 줌, 스와이프, 드래그)로 동작하는 기능은 단일 클릭이나 탭 버튼으로도 동등하게 실행할 수 있어야 합니다.

점검 기준 (Pass)

  • 지도/이미지 확대 시 핀치 외에 [+], [-] 확대/축소 버튼 제공
  • 슬라이더 드래그 외에 직접 숫자 입력 또는 증감 버튼 제공

오류 기준 (Fail)

  • 스와이프 제스처로만 다음 슬라이드로 넘어갈 수 있는 캐러셀
2.1.4

단축키 지원 (충돌 방지)

지침 2.1 입력장치 접근성 보조기술

단일 문자 단축키는 보조기술(스크린 리더의 단축키 등)과 충돌할 수 있으므로 끄기 기능 또는 보조키(Ctrl, Alt 등) 조합으로 제공해야 합니다.

2.2.1

응답 시간 조절 (세션 연장)

지침 2.2 충분한 시간 제공 고령자

시간제한이 있는 콘텐츠(자동 로그아웃, 시험 등)는 시간 만료 전 경고를 제공하고 최소 20초 이상의 시간 연장 수단을 제공해야 합니다.

점검 기준 (Pass)

  • 만료 1~2분 전 알림 다이얼로그와 함께 '시간 연장' 버튼 제공

오류 기준 (Fail)

  • 사전 예고나 연장 옵션 없이 즉시 세션이 만료되는 경우
2.2.2

정지 기능 제공 (캐러셀/자동 변경)

지침 2.2 충분한 시간 제공 인지장애

자동으로 전환되거나 스크롤되는 콘텐츠(배너 슬라이드, 티커 등)는 사용자가 멈출 수 있는 정지(일시정지) 버튼을 명확히 제공해야 합니다.

2.3.1

깜빡임과 번쩍임 제한

지침 2.3 광과민성 발작 예방 안전보장

광과민성 발작을 유발하지 않도록 초당 3~50회의 주기로 강하게 번쩍이거나 깜빡이는 시각 효과를 사용해서는 안 됩니다.

2.4.1

반복 영역 건너뛰기 (스킵 링크)

지침 2.4 쉬운 내비게이션 키보드사용자

반복되는 상단 메뉴를 거치지 않고 본문 주요 콘텐츠로 바로 이동할 수 있는 건너뛰기 링크를 문서 최상단에 제공해야 합니다.

2.4.2

제목 제공 (페이지/프레임/섹션)

지침 2.4 쉬운 내비게이션 스크린리더

웹페이지(<title>), 프레임(<iframe title="...">), 콘텐츠 블록에는 내용을 유추할 수 있는 명확한 제목을 제공해야 합니다.

2.4.3

적절한 링크 텍스트

지침 2.4 쉬운 내비게이션 정보탐색

링크 텍스트는 주변 문맥 없이도 이동할 목적지나 동작을 명확히 알 수 있어야 합니다. ("더보기", "여기" 등 모호한 단어 지양)

점검 기준 (Pass)

  • [공지사항 더보기], [2026 채용공고 바로가기]처럼 목적 명시

오류 기준 (Fail)

  • 목적지가 다른 여러 링크가 모두 "자세히 보기"로만 작성된 경우
2.4.4

블록 조작 (긴 콘텐츠 제어)

지침 2.4 쉬운 내비게이션 탐색효율

긴 분량의 반복되는 블록 목록이나 사이드바 콘텐츠는 접기/펼치기 기능을 제공하여 효율적으로 건너뛸 수 있어야 합니다.

2.4.5

위치 정보 제공 (Breadcrumb / 사이트맵)

지침 2.4 쉬운 내비게이션 길찾기

웹사이트의 전체 계층 구조 내에서 사용자의 현재 위치를 알 수 있는 정보(브레드크럼, 메뉴 활성 표시, 사이트맵)를 제공해야 합니다.

2.4.6

조작 가능 크기 (최소 24×24px)

지침 2.4 쉬운 내비게이션 터치사용자 KWCAG 2.2 신규

버튼, 체크박스, 아이콘 링크 등 모든 조작 컨트롤의 유효 타깃 크기는 최소 24×24px 이상이어야 합니다. (인라인 링크 및 브라우저 기본 제외)

점검 기준 (Pass)

  • 작은 아이콘 버튼이라도 패딩을 주어 24px 이상의 클릭 영역 확보

오류 기준 (Fail)

  • 닫기(X) 버튼 등의 클릭 영역이 12×12px처럼 작아 오작동을 유발하는 경우
2.4.7

초점 표시 (Focus Indicator)

지침 2.4 쉬운 내비게이션 키보드사용자

키보드 초점을 받는 모든 요소는 브라우저 기본 포커스 링을 제거(outline: none)하지 않고 명확한 시각적 테두리를 유지해야 합니다.

3. 이해의 용이성 (Understandable)

3개 지침 · 7개 검사항목
3.1.1

기본 언어 표시

지침 3.1 가독성 스크린리더

웹페이지 최상단 <html> 요소에 해당 문서의 주 언어를 lang="ko"와 같이 올바르게 표기해야 합니다.

3.1.2

언어 변화 표시

지침 3.1 가독성 다국어

본문 중 주 언어와 다른 외래어 문장이나 단락이 길게 포함될 경우 <span lang="en">과 같이 부분 언어를 명시합니다.

3.2.1

사용자 요구에 따른 실행 (예측성)

지침 3.2 예측 가능성 예측가능성

포커스 진입이나 선택(select 변경)만으로 사용자의 의도와 무관하게 새 창이 열리거나 양식이 자동 제출되어서는 안 됩니다.

점검 기준 (Pass)

  • 셀렉트박스 변경 후 별도의 [이동] 또는 [확인] 버튼을 눌러 실행되도록 구현
  • 새 창 링크 시 title="새 창으로 열림" 명시

오류 기준 (Fail)

  • 드롭다운 옵션을 키보드 화살표로 탐색하는 순간 즉시 페이지가 이동해버림
3.2.2

일관성 있는 내비게이션

지침 3.2 예측 가능성 인지장애

웹사이트의 모든 페이지에서 공통적으로 노출되는 내비게이션 메뉴(GNB, LNB)의 배치 순서와 구성은 일관되어야 합니다.

3.2.3

일관성 있는 식별

지침 3.2 예측 가능성 사용성

사이트 내에서 동일한 기능을 수행하는 컴포넌트나 버튼(검색, 장바구니 등)은 페이지마다 다른 라벨이나 모양으로 혼란을 주지 않아야 합니다.

3.3.1

오류 정정 안내

지침 3.3 입력 지원 입력편의

입력 오류가 발생했을 때 오류가 발생한 위치와 원인을 텍스트로 명확히 알려주고, 오류 필드로 즉시 초점을 이동시켜야 합니다.

3.3.2

레이블 제공 (폼 컨트롤)

지침 3.3 입력 지원 스크린리더

모든 입력 폼(input, select, textarea)에는 어떤 값을 입력해야 하는지 명확한 <label> 요소를 1:1로 매핑해야 합니다.

올바른 마크업
<label for="user-phone">휴대폰 번호</label>
<input type="tel" id="user-phone" placeholder="010-0000-0000">

4. 견고성 (Robust)

1개 지침 · 3개 검사항목
4.1.1

마크업 오류 방지 (문법 유효성)

지침 4.1 호환성 보조기술호환

마크업 언어(HTML)의 요소는 시작과 종료 태그가 올바르게 닫혀야 하며, 동일 문서 내에서 중복된 id 속성이 없어야 합니다.

점검 기준 (Pass)

  • W3C 문법 검사기 통과 및 태그 열고 닫힘 무결성 확보
  • 한 페이지 내 모든 id 속성값의 고유성 보장

오류 기준 (Fail)

  • 동일한 id("btn-submit")가 2개 이상 존재하는 경우
4.1.2

웹 애플리케이션 접근성 준수 (WAI-ARIA)

지침 4.1 호환성 동적UI

스크립트로 동작하는 커스텀 UI(아코디언, 탭, 드롭다운, 모달)에는 요소의 역할(role)과 상태(aria-expanded, aria-selected 등)를 올바른 ARIA 속성으로 전달해야 합니다.

ARIA 구현 예시
<button type="button" aria-expanded="false" aria-controls="faq-content-1">
  질문 1번 보기
</button>
<div id="faq-content-1" hidden>답변 내용...</div>
4.1.3

상태 메시지 알림 (Live Region)

지침 4.1 호환성 실시간알림 KWCAG 2.2 신규

페이지를 새로고침하지 않고 동적으로 추가되는 안내 문구(검색 결과 건수, 장바구니 담김 알림 등)는 aria-live="polite" 또는 role="status"로 보조기술에 즉시 전달되어야 합니다.
